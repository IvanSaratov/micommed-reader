# Просмотр HEALDATA в браузере

Статический сайт: TypeScript + Vite + ECharts, Go-библиотека работает через WebAssembly в Web Worker. Нужны Go 1.26+, Node.js 22.12+ и npm. Версии JS-зависимостей зафиксированы в `package-lock.json`.

Из каталога `web/`:

```sh
npm ci
npm run dev
```

Откройте адрес Vite. Выберите один дневной файл, несколько файлов одной выгрузки или ZIP; доступно перетаскивание. Для переименованного файла укажите отчётную дату. Сутки аппарата начинаются в 09:00. Например, синтетический `research/fixtures/clock.bin` открывается с датой `2001-02-03`.

На экране сеанса видны время начала и окончания, продолжительность записи, число апноэ и гипопноэ и AHI. График давления объединяет совпадающие показания. На участках расхождения второе значение видно пунктиром. Пятый канал свёрнут по умолчанию и раскрывается нажатием на его название. Под графиками расположена лента событий с общей шкалой времени. Название строки открывает расшифровку. Рядом указано количество событий этого типа за весь сеанс. Наведение или касание отметки показывает время и число повторов за эту минуту.

Над каждым графиком есть краткое объяснение показателя. Общие определения сверены со [справочником ResMed](https://www.resmed.co.uk/professionals/documentation/glossary/) и [описанием CPAP от NHLBI](https://www.nhlbi.nih.gov/health/cpap). Эти источники объясняют термины, но не подтверждают соответствие каналов формата RC-C60: предварительные трактовки и неизвестное назначение пятого канала остаются явно отмечены.

Сеансы строятся Go-библиотекой по временным отметкам измерений и событий. Соседние фрагменты одного источника объединяются при перерыве **не более 60 минут**, включая переход через 09:00. Более длинный перерыв разделяет сеансы даже внутри одного файла. Конфликтующие версии и записи с недостоверным временем не объединяются автоматически; сайт сообщает о них. Точные дубликаты учитываются один раз. В Go API подтверждённый DeviceID имеет приоритет над SourceID, как и при расчёте периода; сайт задаёт один контекст для выбранной выгрузки.

«Продолжительность записи» — интервал между первой и последней наблюдаемой минутой, включая короткие перерывы; это не измеренная длительность сна. AHI сеанса рассчитывается по сумме событий 102/103/104 и минут аппарата, только когда дневные записи целиком относятся к этому сеансу и позволяют расчёт. Если один день делится между сеансами, аппаратная суточная длительность не распределяется искусственно: вместо AHI выводится «—» с объяснением. Суточные показатели доступны через CLI и Go API.

На компьютере масштаб меняется через Shift + колесо, а перетаскивание перемещает выбранный участок. Обычное колесо прокручивает страницу, даже если курсор находится над графиком. Кнопка «Весь сеанс» возвращает полную ось времени. В компактной подсказке рядом с курсором показаны только значения активного графика и время ближайшего фактического измерения. У края экрана подсказка меняет сторону. Между соседними точками она остаётся видимой; через разрывы данные не переносятся, промежуточные значения не вычисляются.

Для экспорта JSON и CSV используйте отдельную CLI. Все вычисления выполняются локально. Названия файлов, записи и отчёты не отправляются по сети и не сохраняются в localStorage/IndexedDB. Закрытие выгрузки, повторное открытие или отмена завершают её воркер. Внешние сервисы, аналитика, аккаунты и сервер обработки не нужны.

Ограничения импорта общие с CLI: 4 096 элементов, 40 МиБ распакованных данных и 40 МиБ каталога ZIP. ZIP читается блоками без извлечения файлов на диск. Прогресс показывает прочитанные элементы; подготовка и хеширование архива отображаются без процента. Поддерживаются современные Chromium и WebKit с WebAssembly и FileReaderSync в выделенном воркере.

## Сборка и размещение

```sh
npm run build
npm run preview
```

Публикуйте **только `web/dist/`** на любом статическом HTTP(S)-хостинге, включая GitHub Pages. Относительные адреса поддерживают размещение в подпути, например `/micommed-reader/`. Открывайте каталог с завершающим `/`. Запуск через `file://` не поддерживается. `wasm_exec.js` копируется из того же Go toolchain, которым собран WASM. Шрифты и графическая библиотека входят в сборку, CDN не используется. Скрипт сборки проверяет разрешённый состав `dist/`; в него не входят примеры, тестовые отчёты, личные записи, source maps или локальные пути. Лицензии зависимостей находятся в `THIRD-PARTY-NOTICES.txt`.

Сайт не устанавливает сервис-воркер: после загрузки необходимых ресурсов обработка открытого набора работает без сети, а для новой загрузки страницы нужен доступ к статическим файлам. При новом открытии запускается новый воркер, который может запросить JS/WASM сайта из браузерного кэша или с хостинга; содержимое выбранных файлов в запросы не попадает.

## Проверка

Из корня репозитория выполните `go test ./...`, затем из `web/`:

```sh
npm run build
npx playwright install chromium webkit
npm test
```

Тесты используют только публичные искусственные записи. Интеграционная проверка WASM запускает настоящий Go CLI и сравнивает JSON целиком и каждую CSV-таблицу побайтно. Также проверяют часы устройства, повторяющиеся минуты, неизвестные события, конфликтующие версии, повреждения, отмену, замену набора, пустой период, узкий экран и отсутствие сетевых запросов при работе с открытой выгрузкой.

`cmd/healdata-wasm/` содержит мост к File API. Переносимый импорт и форматирование отчётов находятся в `internal/report/`; вычисления остаются в корневой Go-библиотеке. В TypeScript нет второй реализации парсера или расчёта AHI.
