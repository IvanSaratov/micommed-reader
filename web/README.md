# Просмотр HEALDATA в браузере

Статический сайт: TypeScript + Vite + ECharts, Go-библиотека работает через WebAssembly в Web Worker. Нужны Go 1.26+, Node.js 22.12+ и npm. Версии JS-зависимостей зафиксированы в `package-lock.json`.

Из каталога `web/`:

```sh
npm ci
npm run dev
```

Откройте адрес Vite. Выберите один дневной файл, несколько файлов одной выгрузки или ZIP; доступно перетаскивание. Для переименованного файла укажите отчётную дату. Сутки аппарата начинаются в 09:00. Например, синтетический `research/fixtures/clock.bin` открывается с датой `2001-02-03`.

Основной экран показывает сеансы сна: выбор записи, время начала и окончания, продолжительность записи, число дыхательных событий и AHI. По умолчанию видны давление и события. «Другие графики» раскрывает дополнительные каналы. В блоке «Подробности» доступны исходные сутки, календарь, диагностика, основания трактовки, таблицы и экспорт.

Сеансы строятся Go-библиотекой по временным отметкам измерений и событий. Соседние фрагменты одного источника объединяются при перерыве **не более 60 минут**, включая переход через 09:00. Более длинный перерыв разделяет сеансы даже внутри одного файла. Порог можно изменить в «Подробностях» от 1 до 240 минут. Конфликтующие версии и записи с недостоверным временем не объединяются автоматически; сайт сообщает о них. Точные дубликаты учитываются один раз. В Go API подтверждённый DeviceID имеет приоритет над SourceID, как и при расчёте периода; сайт задаёт один контекст для выбранной выгрузки.

«Продолжительность записи» — интервал между первой и последней наблюдаемой минутой, включая короткие перерывы; это не измеренная длительность сна. AHI сеанса рассчитывается по сумме событий 102/103/104 и минут аппарата, только когда дневные записи целиком относятся к этому сеансу и позволяют расчёт. Если один день делится между сеансами, аппаратная суточная длительность не распределяется искусственно: вместо AHI выводится «—» с объяснением. Суточные показатели остаются в подробностях.

Под графиками находится общий ползунок масштаба; на компьютере также работают Shift + колесо и перетаскивание. Кнопка «Весь сеанс» возвращает его полную ось времени. В подробном просмотре суток доступны отдельный сброс масштаба, точные исходные индексы и таблица с клавиатуры.

«Скачать день» экспортирует все версии выбранной даты по правилам CLI. «Скачать период» использует последние рассчитанные включительные границы. JSON совпадает со схемой CLI; CSV скачивается ZIP-архивом из восьми таблиц. Все вычисления и подготовка файлов выполняются локально. Названия файлов, записи и отчёты не отправляются по сети и не сохраняются в localStorage/IndexedDB. Закрытие выгрузки, повторное открытие или отмена завершают её воркер. Внешние сервисы, аналитика, аккаунты и сервер обработки не нужны.

Ограничения импорта общие с CLI: 4 096 элементов, 40 МиБ распакованных данных и 40 МиБ каталога ZIP. Браузерный экспорт ограничен 128 МиБ результата, чтобы ограничить временный Blob; при превышении выберите меньший период. ZIP читается блоками без извлечения файлов на диск. Прогресс показывает прочитанные элементы; подготовка и хеширование архива отображаются без процента. Поддерживаются современные Chromium и WebKit с WebAssembly и FileReaderSync в выделенном воркере.

## Сборка и размещение

```sh
npm run build
npm run preview
```

Публикуйте **только `web/dist/`** на любом статическом HTTP(S)-хостинге, включая GitHub Pages. Относительные адреса поддерживают размещение в подпути, например `/micommed-reader/`. Открывайте каталог с завершающим `/`. Запуск через `file://` не поддерживается. `wasm_exec.js` копируется из того же Go toolchain, которым собран WASM. Шрифты и графическая библиотека входят в сборку, CDN не используется. Скрипт сборки проверяет разрешённый состав `dist/`; в него не входят примеры, тестовые отчёты, личные записи, source maps или локальные пути. Лицензии зависимостей находятся в `THIRD-PARTY-NOTICES.txt`.

Сайт не устанавливает сервис-воркер: после загрузки необходимых ресурсов обработка открытого набора работает без сети, а для новой загрузки страницы нужен доступ к статическим файлам. При новом открытии запускается новый воркер, который может запросить JS/WASM сайта из браузерного кэша или с хостинга; содержимое выбранных файлов в запросы не попадает.

## Проверка

Из корня репозитория выполните `go test ./...`, затем из `web/`:

```sh
npm run build
npx playwright install chromium webkit
npm test
```

Тесты используют только публичные искусственные записи. Они запускают настоящий Go CLI и сравнивают JSON целиком и каждую CSV-таблицу побайтно. Также проверяют часы устройства, повторяющиеся минуты, неизвестные события, конфликтующие версии, повреждения, отмену, замену набора, пустой период, узкий экран и отсутствие сетевых запросов при работе с открытой выгрузкой.

`cmd/healdata-wasm/` содержит мост к File API. Переносимый импорт и форматирование отчётов находятся в `internal/report/`; вычисления остаются в корневой Go-библиотеке. В TypeScript нет второй реализации парсера или расчёта AHI.
